# 剧情复刻工作流程

“能播放”和“与原版一致”是两项不同结论。复刻目标按每个事件的 **进入前状态 → 触发条件 → 并发演出 → 等待/分支 → 完成后世界状态** 审核。配置里没有的默认值也必须追到原生构造器/初始化逻辑，不能把缺省当成零或关掉。

## 1. 固定版本和输入

先记录 APK、地图、event JSON、Lua、Collider/Prefab bundle 的 SHA，使用同一版本的认证代码段。建立资料入口：`native-workbench.py prepare`。若 Lua 与编译代码行为不同，检查 native C# 替代、IFix/hotfix、实际运行入口和调用链，再确定哪个版本生效。1-1 开场和追逐已有这种差异；Lua 原文出现重复 goblin1 不代表原生实机就让第三只哥布林停住。

地图必须逐字段解析并保留来源、未消费范围、枚举原始值、float32 位模式。未知字节先登记偏移与长度；不能丢弃后宣称“每字节已还原”。关卡运行数据可以简化存储，但必须能反向定位原始字段或汇编 load/store。

## 2. 构造事件图，而非只摘台词

对每个事件列出：原生 handle 命名空间、地图触发体、出生/预摆位置、开局可见性、触发前置 flag、碰撞/区域进入算法、重复触发策略、主动接触/按键交互差异、各分支及汇合、存档恢复入口。地图 preview 的 marker、剧情 NPC、机关 handle 不能仅凭同名混用。

触发前的世界也属于演出：公主是否已躺下、追逐演员是否已在场外准备、倒地哥布林是否已显现、门是否已经打开。资源预热不等于剧情开始；预热完成前不应提前提交 flag 或让移动计时耗掉。

## 3. 逐条恢复动作契约

| 原生行为 | 必须取得的证据 |
| --- | --- |
| Move/MoveWaypoints | 绝对/相对坐标、坐标原点、地面高度、速度或时长、是否寻路、是否等待到达 |
| 跳跃 | 起点条件、水平位移和竖直曲线分离、持续时间、落地切动作、随行者的起跳偏移 |
| Pose/上半身动作 | Spine action 名、朝向枚举、上下轨、开始时钟、是否循环、是否重启动作 |
| 颤动/受击/起身 | 原生半径、相位/随机来源、衰减、方向、与基础位置的叠加顺序 |
| 倒吊/举起 | 挂点骨骼、父子坐标、绳末端接脚、动画原点、物理更新频率、解除后的地面位置 |
| 镜头 | 正交尺寸、视角、平移/跟随、缩放曲线、截图对应的分辨率/宽高比 |
| 门/机关 | 初始状态、状态机迁移、动画开始/结束、碰撞何时启停、音频和 jingle 是否分别触发 |
| 台词/选择/UI | 原生 prefab、语言 key、逐字间隔、确认等待、选择颜色/图标、HUD 显隐时点 |
| 物品/宝箱 | 弹出→落地/悬浮→吸收→特效→说明 UI，每阶段等待条件和保存时点 |
| 音频 | SoundHandleSpec 内码、Volume/Pitch/Loop、开始/停止、混音器组和快照 |

本机地图逻辑坐标统一使用 `[X,Y,Z]`；转换到 Three.js 时是 `[X,Y,-Z]`。KONG 层级高程换算和本地偏移在数据导出边界做一次。世界坐标、Spine 像素单位、UI 像素、骨骼局部坐标不要互相补偿；修“看起来偏一点”必须先找到坐标链中的错误。

原生寻路请求必须走实际碰撞数据和原生路径规则。不能因为起终点正确，就把穿墙直线当成寻路；也不能拿浏览器 A* 的任意 tie-break 证明路径完全一致。

## 4. 保留原生并发与等待

区分游戏时钟、剧情时钟、动作时钟、逐字时钟和物理时钟；用户停留在对话框/选择框时，哪些时钟继续走必须由原生行为决定。后台追逐不能阻塞骑士，但也不能等骑士已经进入屏幕才启动哥布林。

将异步调用恢复为事件依赖图：`移动完成 → 下一段对白`、`按钮到达并按下 → 绳解除 → 骑士落地/坐起 → 罗兰茵走到身边 → 对话 → 入队`。不得用估计的总时长代替完成回调。速度移动的时长取实际路径长度；动作重播要重新绑定原生 Spine 时钟。

手动挣扎等片段是输入状态，不能当作自动时间轴空白：明确进入、可接受按键、完成条件、超时/暂停、恢复和分支接续。所有分支要有完整收尾，清除挂点、控制锁、镜头、循环音和临时演员。

## 5. 编译和证据账本

共性行为落到 gtmap/gtAudio 核心，关卡数据放到 stage manifest；仅原生关卡专用逻辑留在关卡适配层。每个常量附字段名或原生地址范围；涉及读取常量池时附保护段认证。配置名、截图与汇编结论不一致时保留矛盾并继续追查，不用截图测量覆盖原生数据。

```powershell
python tools/native/audit-stage.py --stage gtonline/assets/stage-1-1.json --evidence gtonline/assets/native-story-evidence.json --out E:\GTFiles\stage-1-1-ledger.json
```

账本列出每个场景及分支的来源、演员、操作、游戏 hook、移动等待和未决项。它是当前编译产物的可检查清单，**不会自动认证视觉一致**。`stage.audit.unknownOperations` 的旧 trace 告警可能早于 native override，必须逐项销账并标版本，不能全部删除，也不能误认为最终演出一定还缺那条台词。

## 6. 一次集中最小验证

先完成相关修改再集中检查。优先验证：所有场景/分支数据能编译，handle 唯一且能定位，所有声音可解析，必需动画存在，等待有解除路径，保存恢复不重复副作用。运行时只走受影响的关键链路：追逐两段及两次跳跃、倒吊输入和各分支、救援入队、物品说明和机关开关；需要时对原生录像的同一时间点/分辨率做局部比较。

只测当前风险，不反复跑整关。静态检查通过不能代替演出验收；尚有随机序列、原生寻路顺序、字体度量或未解字段时，明确标为未认证。所谓“0 差别”必须同时覆盖触发前、播放中、分支、输入和结束后的状态，不能靠单张截图或“未报错”宣布完成。
